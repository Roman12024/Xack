# ИТ Школа Ростелеком — CRM контроля взаимодействия с вузами

Система контроля и обработки статистических данных по обучению студентов вузов и школ по ИТ-направлениям. Реализация технического задания (2026).

Платформа объединяет **CRM для сотрудников ИТ Школы** (взаимодействие с вузами, workflow из 14 этапов, отчёты, аналитика) и **публичную витрину** для участников (курсы, ИТ-проекты, запись и заявки).

---

## Возможности

### Для руководителя и администратора (staff)

| Блок | Возможности |
|---|---|
| **Взаимодействия** | Таблица взаимодействий с вузами: фильтры (период, вуз, направление, продукт, статус, ответственный — с автоприменением), прогресс-бар этапа workflow (X из 14), карточка с таймлайном переходов, комментариями и вложениями (png, jpeg, pdf, zip, gzip, rar, doc, docx, xls, xlsx) |
| **Workflow** | Базовая цепочка из 14 статусов из ТЗ (поиск контактов → контроль исполнения); администратор создаёт новые workflow и переименовывает статусы |
| **Каталоги** | ВУЗы (с полями ТЗ: вендор, ПО, договор, лицензия, менеджер и т.д.), ИТ-направления, ИТ-продукты; импорт вузов из **xls/xlsx** по согласованному маппингу колонок |
| **Курсы и ИТ-проекты** | Создание карточек с фото-обложкой, сроками, описанием программы и требованиями «кто может участвовать»; редактирование и удаление; сортировка (по датам/названию/направлению, ↑↓); завершённые скрыты от пользователей и помечены «Завершён» для staff |
| **Заявки** | Все заявки участников (на курсы и проекты), смена статуса «Новая → На рассмотрении → Одобрена/Отклонена» с комментарием-ответом |
| **Участники** | Записи на курсы; в карточке курса — список участников с **полным профилем** каждого |
| **Отчёты и статистика** | Выгрузка **xlsx/pdf** за период (вуз, направление, продукт, статус, ответственный), диаграммы PNG, интерактивная статистика по фильтрам |
| **Досье пользователя** | Кнопка «Открыть» у любого пользователя: полный профиль, **телеметрия по каждому устройству** — IP, модель устройства (iPhone/Pixel и т.д.), ОС, браузер, заряд батареи, время на сайте, последний вход, сведения о cookie/localStorage, все сессии и заявки |
| **Администрирование** | Пользователи: создание, смена ролей; workflow |

### Для пользователя (участника)

- **Курсы** и **ИТ-проекты**: карточки с фото, сроками (цвет дедлайна: 🟢 > недели, 🟡 до недели, 🔴 последний день), подробным описанием и требованиями
- Кнопка **«🚀 Участвовать»** — запись + автоматическая заявка в один клик
- **Мои заявки**: статус обработки (цветной) и ответ руководителя
- **Профиль**: ФИО, телефон, дата рождения, город, организация, должность, образование, навыки, Telegram, портфолио, «О себе», аватар
- Регистрация по **e-mail** с письмом-подтверждением; обязательная галочка **пользовательского соглашения** (152-ФЗ)
- Баннер **cookie** с подробным описанием используемых файлов

## Технологии

- **Back-end:** Python 3.12, FastAPI, Uvicorn
- **БД:** SQLite (файл в volume); схема совместима с PostgreSQL
- **Front-end:** SPA (vanilla JS, fetch, без перезагрузки страницы), дизайн-система Ростелекома (gen2 / «Атомаро», Rostelecom Light Theme + тёмная)
- **Отчёты/графика:** openpyxl (xlsx), reportlab (pdf), matplotlib (png)
- **Авторизация:** JWT (HS256) + роли user/manager/admin; точка подключения Keycloak (профиль `sso` в docker-compose)
- **Инфраструктура:** Dockerfile, docker-compose, volume для данных

## Быстрый старт (Docker)

```bash
unzip rtk_crm.zip && cd rtk_crm
docker compose up -d --build
# открыть http://localhost:8000
```

Если проект уже запускался раньше и нужна чистая БД с демо-данными:

```bash
docker compose down -v && docker compose up -d --build
```

## Без Docker (Python 3.10+)

```bash
pip install -r requirements.txt
uvicorn app.main:app --port 8000
```

## Демо-доступы (создаются автоматически)

| Логин | Пароль | Роль |
|---|---|---|
| admin | Admin123! | Администратор платформы |
| manager | Manager123! | Руководитель |
| kam1 / kam2 | Kam123! | Пользователь (участник) |

Новые пользователи регистрируются по e-mail: приходит письмо со ссылкой подтверждения. SMTP настраивается переменными `RTK_SMTP_HOST/PORT/USER/PASS/FROM`; без SMTP письмо сохраняется в `data/outbox/`, а ссылка дублируется в ответе API и на экране (dev-режим).

## Ключевые API-эндпоинты

- `POST /api/auth/register|login|confirm` — регистрация по e-mail, вход, подтверждение
- `GET/POST/PUT/DELETE /api/universities|directions|products` — каталоги
- `POST /api/catalogs/import` — импорт вузов из xlsx
- `GET/POST /api/courses`, `POST /api/courses/{id}/enroll`, `GET /api/courses/{id}/participants` — курсы, запись, участники
- `GET/POST/PUT/DELETE /api/products` — ИТ-проекты (FormData + фото)
- `POST/GET /api/applications`, `PUT /api/applications/{id}/status` — заявки и их обработка
- `GET /api/interactions`, `POST /api/interactions/{id}/transition` — взаимодействия и переходы статусов
- `GET /api/reports/export?fmt=xlsx|pdf`, `GET /api/reports/chart.png`, `GET /api/reports/stats` — отчёты и статистика (только staff)
- `GET/PUT /api/profile`, `POST /api/profile/avatar` — профиль
- `GET /api/telemetry/session`, `POST /api/telemetry/ping|cookies` — телеметрия сессии
- `GET /api/users/{id}/full` — досье пользователя (manager/admin)

Интерактивная документация (Swagger UI): **/docs**

## Ролевая модель

- **Пользователь** — «витрина услуг»: курсы, ИТ-проекты, участие и заявки, свой профиль. Служебные данные (статистика, отчёты, IP/устройства, списки участников, досье) скрыты и на уровне API (403).
- **Руководитель** — все операции с данными + назначение ответственных, обработка заявок, досье.
- **Администратор** — управление пользователями, ролями, workflow, разграничение доступа.

## Безопасность

- Пароли: PBKDF2-HMAC-SHA256, 100 000 итераций, случайная соль
- JWT 8 ч, секрет — переменная `RTK_SECRET`; проверка ролей на каждом защищённом эндпоинте (401/403)
- Подтверждение e-mail до первого входа; одноразовые токены подтверждения
- Пользовательское соглашение при регистрации; фиксация согласия на cookie
- Валидация расширений и размеров файлов, UUID-имена на диске; защита от SQL-инъекций (параметризованные запросы)
- Требования 152-ФЗ и приказа ФСТЭК № 117: разграничение доступа, аудит действий (история переходов, сессии, телеметрия), хранение персональных данных в защищённой БД
- Исходный код открыт, без обфускации

## Интеграции

1. **LMS и веб-сайт (CMS Laravel):** приём заявок по JSON через `POST /api/interactions` и `POST /api/applications`; контракт API согласуется с заказчиком.
2. **Keycloak:** `docker compose --profile sso up -d` поднимает Keycloak (:8080); замените `verify_token` на проверку RS256 realm-ключа — ролевая модель сохраняется.
3. **SMTP:** переменные окружения для реальной отправки писем подтверждения.

## Производительность

- Отклик интерфейса < 1 с: SPA без перезагрузки, автоприменение фильтров
- Stateless API, uvicorn workers=2; отчёты формируются в памяти и отдаются потоком
- Целевая нагрузка: 50 параллельных пользователей, ≥ 10 параллельных отчётов
